# Avito RecSys: графовый retrieval + CatBoost

Рекомендация объявлений Avito по данным [AvitoTech ML CUP 2026](https://www.kaggle.com/datasets/nikitakuznetsof/avito-ml-cup-2026): для пользователя предсказать до 160 **новых** объявлений, с которыми он свяжется с продавцом в следующую неделю. Метрика — Recall@160, усреднённый по пользователям.

5 млрд событий (38 GB, 100 партиций), ~110 млн объявлений. Весь пайплайн — один ноутбук [`final.ipynb`](final.ipynb): один переключатель объёма `SAMPLE`, CPU или GPU выбирается сам.

|---|---|---|---|
| **v2** | 0.01 (1 партиция) | ноутбук, CPU, ~60 мин | **0.1327** [0.1252; 0.1400], 7 131 юзер |
| v1 | 0.01 | ноутбук, CPU, 15–30 мин | 0.1227 [0.115; 0.130] |
| v1 | 0.3 | A100 80 GB, 28 мин | 0.1175 [0.1154; 0.1195], 76 081 юзер |

Метрики при разных `SAMPLE` считаются на разных пользователях: квоты по вертикалям меняют состав. С 30% на 75% выросли все бакеты.

## Как устроено

```
события (контакт ×3, показ ×0.3, клик ×1), история 28 дней до порога
  │
  ├─ Retrieval: seed-ы юзера (100 последних, затухание τ = 7 д) × H1 × H2 → top-1000 на источник, минус виденное
  │    cr     блуждание item → юзер × категория × регион → item     главный источник
  │    s24    блуждание item → юзер × день → item
  │    u0     блуждание item → юзер → item (RP3, β = 0)
  │    covis  co-visitation: тот же граф s24, сырые веса
  │    bm25   тот же граф u0, веса BM25
  │    sp     популярное в главных сегментах s0 × loc юзера
  │    → ~3 000 кандидатов на юзера, потолок пула 0.255 (1%)
  │
  ├─ Признаки (56): скор и ранг каждого источника · динамика item (события, показы,
  │    контакты за 1/7/14 дней, тренды, возраст) · атрибуты item · юзер ·
  │    аффинити юзера к атрибутам кандидата (доля, давность, контакты)
  │
  └─ CatBoost YetiRank, глубина 6, 50 случайных негативов на юзера → top-160
```

**Валидация.** Глобальный временной сплит на всех шагах: граф, признаки и пул объявлений строятся только по событиям до порога. Ранкер учится на неделе W1 (порог T − 7 д), тест — неделя W0. Эксперименты обучаются на W2 и проверяются на W1, тест W0 используется один раз в конце. Решения по ранкеру принимаются по среднему приросту на 5 сидах: разброс одного обучения (~±0.002) сравним с эффектами.

**Масштаб.** Графы на GPU через cupy, на CPU тот же код через scipy. Граф делится на блоки меньше 2³¹ связей (индексы cupyx — int32): на 100% граф `s24` — ~2.4 млрд связей. Этапы сохраняют чекпоинты (`univ.npz` → `model.cbm` → `top160.parquet`), повторный запуск продолжает с последнего готового. Smoke-тест всего пути на 3% юзеров идёт первым и занимает 1–5 минут.

## Запуск

Данные: 38 GB, токен Kaggle не нужен, повторный запуск докачивает недостающее.

```bash
python scripts/download_kaggle.py              # всё -> data/raw/
python scripts/download_kaggle.py --parts 30   # только part_000..029 (для SAMPLE = 0.3)
```

**Docker** (нужен NVIDIA Container Toolkit; без `--gpus all` — на CPU). Контейнер сам докачивает данные в смонтированный `data/` и запускает ноутбук:

```bash
docker build -t avito .
docker run -d --name avito --gpus all --restart on-failure:3 -e SAMPLE=1.0 -e USERS=0.5 -v $PWD/data:/app/data avito
docker logs -f avito
```

**Без Docker** (нужен Python ≥ 3.11; пакеты точных версий ноутбук ставит сам):

```bash
jupyter nbconvert --to python final.ipynb && sed -i 's/^SAMPLE = 0.01/SAMPLE = 1.0/; s/^USERS = 1.0/USERS = 0.5/' final.py
setsid nohup python final.py > run.log 2>&1 < /dev/null &
```

Через 1–5 минут в логе появится Recall smoke-теста. Если вместо него ошибка, дальше не ждать. Результат: `data/final/sample_<SAMPLE>/metrics.json` (Recall, CI, бакеты, время) и `top160.parquet`.

Ресурсы: 1% — ноутбук с 11 GB RAM на пределе (своп). Сервер: 64 GB RAM, A100 80 GB. 75% (v1) — пик 43 GB RAM и графы ~30 GB VRAM. При `SAMPLE ≥ 0.5` графы строятся по одному за проход.

`USERS` — доля юзеров окон W1/W0 (по хэшу), по умолчанию 1.0. Память под кандидаты и признаки линейна по ней, а граф строится по всем данным, поэтому плотность графа (источник роста метрики) не страдает. В v2 кандидатов на юзера втрое больше, чем в v1: при 64 GB RAM на `SAMPLE = 1.0` берите `USERS = 0.5` (пик v2 ещё не измерен; при нехватке памяти процесс убивается без traceback — лог просто обрывается) (~50k юзеров, CI ±0.003). Результат пишется в `data/final/sample_<SAMPLE>_users_<USERS>/`.

## Что пробовали

Всё измерено на одной схеме валидации и записано в [docs/experiments.md](docs/experiments.md). Разбор retrieval против решений топ-3 — в [docs/retrieval_analysis.md](docs/retrieval_analysis.md).

| | Прирост | Эксперимент |
|---|---|---|
| Сущность юзер × категория × регион вместо юзера | +0.031 / +0.008 | 4 |
| Глубина top-500 → top-1000 на источник | +0.006–0.007 | 6г |
| co-visitation + BM25 как источники | +0.0035 ± 0.0012 | 6е |
| Популярное в сегментах s0 × loc | +0.0023 ± 0.0008 | 6е |
| β = 0, показы с весом 0.3, τ = 7 д | | 4 |

Не дали прироста:
- co-visitation и BM25 только как признаки;
- сложные негативы (−0.025);
- флаг «категория закрыта»;
- frontier, фильтр свежести, затухание рёбер — на 1% их не оценить, проверка на 30%;
- контентная близость по semantic ID;
- старая история для юзеров без свежей;
- прогноз динамики item (Chronos): граница-оракул +0.009.

Куда теряются таргеты (1%): ~13% найдены, ~5% потеряны ранкером, 11% за отсечкой, **52% недостижимы** одношаговым блужданием (хвост в своих категориях, у объявления 1–3 юзера), 12% без событий за 28 дней, 6% у юзеров без свежей истории.

## Утечка в старом пайплайне

Ранние версии строили ALS, co-visitation, пул item и признаки по данным, перекрывавшим окно таргета. Метрики были завышены в 1.6–6.3 раза и **по-разному для разных методов**, так что сравнение методов между собой тоже было некорректным.

| Метод | С утечкой | Честно | Завышение |
|---|---|---|---|
| Popular | 0.0078 | 0.0048 | ×1.6 |
| ALS | 0.0368 | 0.0137 | ×2.7 |
| Co-visitation | 0.1357 | 0.0216 | ×6.3 |
| CatBoost ranker | 0.1613 | 0.0325 | ×5.0 |

Разбор: [docs/leakage_audit.md](docs/leakage_audit.md). Старый пайплайн сохранён в `src/` и воспроизводится: `bash scripts/run_pipeline.sh synth` (честно) / `leaky` (с утечкой).

## Структура

```

docs/
├── experiments.md             # все эксперименты: гипотеза -> метрика -> время -> вердикт

src/, scripts/*.sh             # старый пайплайн (ALS + covisit) и его воспроизведение
```
